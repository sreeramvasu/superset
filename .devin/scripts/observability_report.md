# Devin Automation Observability Dashboard

## Overview
The observability dashboard provides insights into the effectiveness of your Devin automation system by tracking success/failure rates, PR creation statistics, and session performance over time.

## Features

### 📊 **Key Metrics Tracked**
- **Total Sessions**: Overall automation attempts
- **Success Rate**: Percentage of successful sessions
- **PR Creation Rate**: Percentage of sessions that created PRs
- **Time Period Analysis**: Statistics for 24h, 7d, and 30d periods
- **Recent Sessions**: Detailed view of the last 10 sessions

### 🎯 **Success/Failure Signals**
- ✅ **Success Indicators**:
  - Sessions that completed without errors
  - PR URLs successfully created
  - Changes committed to repository
  
- ❌ **Failure Indicators**:
  - Sessions that timed out or encountered errors
  - Missing PR URLs
  - Error messages and failure reasons

### 📈 **Dashboard Components**
1. **Summary Cards**: Visual overview of key metrics
2. **Time Period Analysis**: Breakdown by time periods
3. **Recent Sessions List**: Detailed session information
4. **PR Links**: Direct links to created pull requests
5. **Error Messages**: Detailed error information for failed sessions

## Usage

### **Run Observability Dashboard**
```bash
# Generate dashboard (uses default logs directory)
python .devin/scripts/observability_dashboard.py

# Specify custom logs directory
python .devin/scripts/observability_dashboard.py /path/to/logs
```

### **Output Files**
- **HTML Dashboard**: `.devin/logs/observability_dashboard.html`
- **JSON Stats**: `.devin/logs/observability_stats.json`

### **View the Dashboard**
Open the generated HTML file in your browser:
```bash
# Windows
start .devin/logs/observability_dashboard.html

# macOS
open .devin/logs/observability_dashboard.html

# Linux
xdg-open .devin/logs/observability_dashboard.html
```

## Integration with Automation

### **Option 1: Manual Review**
Run the dashboard periodically to review automation performance:
```bash
python .devin/scripts/observability_dashboard.py
```

### **Option 2: Automatic Reporting**
Add to your GitHub workflow to generate reports after each automation run:

```yaml
- name: Generate Observability Report
  if: always()
  run: |
    python .devin/scripts/observability_dashboard.py
    echo "Observability dashboard generated"
```

### **Option 3: Scheduled Reports**
Set up a cron job or GitHub Actions schedule to generate regular reports:
```yaml
# .github/workflows/observability-report.yml
on:
  schedule:
    - cron: '0 9 * * *'  # Daily at 9 AM
  
jobs:
  observability:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Generate Dashboard
        run: python .devin/scripts/observability_dashboard.py
      - name: Upload Dashboard
        uses: actions/upload-artifact@v4
        with:
          name: observability-dashboard
          path: .devin/logs/observability_dashboard.html
```

## Metrics Interpretation

### **Success Rate**
- **> 80%**: Excellent automation performance
- **60-80%**: Good performance, some optimization needed
- **< 60%**: Needs investigation and improvement

### **PR Creation Rate**
- **> 70%**: Good automation effectiveness
- **50-70%**: Moderate effectiveness
- **< 50%**: Low effectiveness, needs improvement

### **Common Failure Patterns**
- **Session Timeouts**: May need longer timeout configuration
- **API Errors**: Check API credentials and permissions
- **Missing PR URLs**: Check for GitHub permissions
- **No Changes**: Issue may be too complex for automation

## Troubleshooting

### **No Sessions Found**
- Check that logs directory exists: `.devin/logs/`
- Verify log files match pattern: `devin-api-result-*.json`
- Run automation to generate log files

### **Dashboard Not Updating**
- Ensure you're using the correct logs directory
- Check file permissions
- Verify log files are being generated by automation

### **Incorrect Statistics**
- Check log file format matches expected structure
- Verify timestamps are correct
- Remove corrupted log files if needed

## Performance Monitoring

### **Recommended Review Frequency**
- **Daily**: During active development and testing
- **Weekly**: During production use
- **Monthly**: For long-term trend analysis

### **Alert Thresholds**
Consider setting up alerts for:
- **Success Rate < 60%**: Needs immediate attention
- **PR Creation Rate < 50%**: Automation not effective
- **Multiple Consecutive Failures**: Possible systemic issues
